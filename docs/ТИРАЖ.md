# Продажа бота другим поставщикам — как это устроено (H3, вариант «копия каждому»)

Решение владельца: **продаём, отдельная копия на каждого клиента**. Один клиент = один
сервер = один бот. Клиенты не влияют друг на друга: сбой у одного не задевает остальных.

## Что получает клиент

- Свой Telegram-бот (своё имя и аватар в BotFather).
- Свой прайс, свои клиенты, свои сотрудники, своя книга долгов.
- Мини-приложение каталога (свой адрес) и страницу сводки для владельца.
- Бэкапы каждый час, проверку восстановления раз в неделю, мониторинг «бот жив».
- Всё на русском, без технических слов.

## Что нужно собрать с клиента (заполняется один раз)

| Что | Где взять | Кто делает |
|---|---|---|
| Файл профиля `clients/<имя>.env` | шаблон в конце этого файла | мы |
| Токен бота | BotFather → `/newbot` | клиент или мы по его просьбе |
| ID чата управляющего и курьера | `/id` в их Telegram | клиент |
| Прайс `catalog.xlsx` | таблица клиента (позиции, цены, фасовки) | клиент |
| Сервер | любой VPS 2 vCPU / 2 ГБ (Ubuntu 24.04+) | мы заводим, клиент оплачивает |
| Домен для мини-аппа (по желанию) | DNS-запись на IP сервера | клиент |

## Порядок установки (1–1,5 часа)

1. Взять чистый VPS, зайти по SSH как root.
2. Поставить git и скопировать код:
   ```bash
   apt-get update -qq && apt-get install -y -qq git
   git clone git@github.com:muradpocta82-code/order_bot.git /opt/order_bot
   ```
   (ключ доступа — свой deploy-ключ на репозиторий, выдаётся один раз)
3. Положить прайс клиента в `/opt/order_bot/catalog.xlsx`.
4. Заполнить профиль `/root/clients/<имя>.env` (шаблон ниже, права 600).
5. Запустить установку:
   ```bash
   cd /opt/order_bot && bash scripts/client_setup.sh /root/clients/<имя>.env
   ```
   Скрипт сам: поставит пакеты, создаст пользователя и базу со случайным паролем,
   соберёт `.env` с правами 600, применит миграции, поднимет службы, прогонит проверки.
6. Прописать мониторинг: `bash scripts/set_external.sh HEARTBEAT_URL <ссылка>`.
7. Проверить в Telegram: `/start` → онбординг заведения → `/price` → тестовый заказ.
8. Передать клиенту короткую памятку (ниже) и доступ к странице `/owner`.

## Профиль клиента (`/root/clients/<имя>.env`)

```ini
CLIENT_NAME=Бар «Бек»
BOT_TOKEN=123456789:AA...
MANAGER_CHAT_ID=123456789
COURIER_CHAT_ID=987654321
WEBAPP_PORT=8443
CATALOG_WEBAPP_URL=https://bot.barbek.uz:8443/
```

## Настройка под клиента без программиста

Всё делается командами в чате бота (менеджеру):

- `/text` — тексты: приветствие, ответы (например, название заведения).
- `/tune` — пороги: минимальный заказ, допуск чека, время в пути.
- `/slots` — интервалы доставки, `/cutoff` — время приёма заказов на завтра.
- `/depot` — координаты склада, `/travel` — сколько минут едет курьер.
- `/price` и `/export` — прайс и выгрузка заказов (в том числе в Google Sheets).

## Что стоит денег и внимания

- Сервер: ~5–10 $/мес за клиента (2 ГБ памяти достаточно).
- Обновления: одна кодовая база, обновление клиента — `git pull` + `scripts/test_all.sh`
  + перезапуск (5 минут). Обновления ставим пачкой, раз в 1–2 недели.
- Поддержка: вопросы клиента в Telegram; типовые ответы — `/help` и памятка.
- **Отдельно решить с юристом**: договор с клиентом, кто оператор персональных данных
  (он или мы), SLA и что входит в поддержку.

## Памятка клиенту (можно отправлять как есть)

> Ваш бот: @… · Сводка для владельца: ссылка из команды `/owner`.
> Повар пишет заказ текстом, голосом или фото — бот разбирает по вашему прайсу,
> считает сумму и передаёт на сборку. Курьер получает карточку, отмечает «Выехал»
> и «Доставлено», клиент видит время прибытия.
> Прайс меняете вы: присылаете новый файл — обновляем. Долги, касса и отчёты — в боте.
