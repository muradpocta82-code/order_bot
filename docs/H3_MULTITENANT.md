# H3: продавать бота другим — что это значит технически

Документ для решения владельца. Ничего не меняет в работе бота, только объясняет цену вопроса.

## Коротко

Сейчас бот — «один бизнес, один прайс, один менеджер». Чтобы продавать его другим
поставщикам, нужно сделать **мульти-тенант**: несколько компаний в одной базе, у каждой
свой прайс, свои клиенты, свои сотрудники и свой Telegram-бот.

Варианты по возрастанию цены:

| Вариант | Что это | Срок | Риск |
|---|---|---|---|
| **A. Не продавать** | оставляем как есть, бот работает на один бизнес | 0 | нет |
| **B. Копия для каждого клиента** | отдельный сервер/бот на каждого покупателя, ставится скриптом | 3–5 дней на автоматизацию установки | низкий: клиенты не влияют друг на друга |
| **C. Мульти-тенант в одной базе** | одна установка, много компаний, разделение по «тенанту» | 3–4 недели работы | средний: ошибка в фильтре = клиент видит чужие данные |

## Что технически придётся поменять (для варианта C)

1. **База**: в каждой таблице — `tenant_id`, во всех запросах фильтр по нему. У нас
   ~40 таблиц и `db.py` на 3 тыс. строк, где всё хранилище в одном классе → это
   самая большая часть работы.
2. **Прайс**: сейчас один файл `catalog.xlsx` и одна таблица позиций → нужно по компании.
3. **Telegram**: один бот = один токен. Либо у каждой компании свой бот (тогда несколько
   процессов), либо один бот с выбором компании по chat_id.
4. **Сотрудники и роли**: `MANAGER_CHAT_ID`/`COURIER_CHAT_ID` из `.env` → в базу, по компании.
5. **Деньги**: книги расчётов, акты, накладные — по компании; нумерация заказов своя.
6. **Настройки**: пороги (`/tune`), тексты (`/text`), слоты, склад — всё станет «на компанию».
7. **Бэкапы и обновления**: одна база со всеми → при ошибке страдают все клиенты;
   нужен staging (он уже есть) и аккуратные миграции.

## Что уже готово в пользу любого варианта

- Тестовый бот и отдельная база (A13) — можно проверять, не рискуя рабочим.
- Приватный репозиторий и точные версии пакетов (A3) — установка воспроизводима.
- `scripts/bootstrap.sh`, `doctor.py`, `scripts/rehearse.sh` — установка и проверки автоматизированы.
- Всё на русском, интерфейс без жаргона — новый клиент разберётся.

## Моя рекомендация

- Если продажа пока «может быть» — **вариант B**: автоматизировать установку (скрипт «поднять
  бота для новой компании на новом сервере за час»). Это в разы дешевле мульти-тенанта и
  не ломает то, что уже работает.
- Вариант C имеет смысл только при 5+ клиентах и готовности платить за поддержку:
  одна установка дешевле в обслуживании, но любая ошибка — общая.

## Что нужно от владельца

Ответ на один вопрос: **продаём или нет**. Если да — какой из вариантов (B или C),
и сколько примерно клиентов ждём в первый год: от этого зависит, что делать первым.
