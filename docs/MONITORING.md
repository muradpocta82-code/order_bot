# Внешний мониторинг (A4) — что нужно сделать владельцу

Внутри бота уже есть:
- цикл `_heartbeat_loop` в `main.py` — раз в 5 минут отправляет запрос на `HEARTBEAT_URL`;
- `GET /health` у мини-приложения каталога (`https://littlemouse.su:8443/health`) — отвечает
  `200 {"ok": true}`, если служба и база живы;
- тревоги по частоте ошибок (`orderbot/watch.py`) — уходят менеджеру в Telegram.

Не хватает только внешнего «наблюдателя», который заметит, если бот умолк целиком.

## Шаги (10 минут)

1. Завести бесплатный аккаунт на **healthchecks.io**.
2. Создать check: период **5 минут**, grace **10 минут**.
3. Скопировать ping-URL вида `https://hc-ping.com/xxxxxxxx-xxxx-…`.
4. В `/opt/order_bot/.env` добавить строку `HEARTBEAT_URL=<этот URL>` и перезапустить бота:
   ```bash
   systemctl restart order_bot
   ```
5. В Healthchecks добавить получателей уведомлений: **почта и/или Telegram** (не через бота —
   бот может быть именно тем, кто упал).
6. Завести проверку сайта на **uptimerobot.com**: тип HTTP(s), адрес
   `https://littlemouse.su:8443/health`, интервал 5 минут, уведомления те же.

## Как проверить, что работает

```bash
systemctl stop order_bot            # бот «упал»
# через 10–15 минут должно прийти письмо/сообщение от Healthchecks и UptimeRobot
systemctl start order_bot           # вернуть бота
# через 5 минут пинги возобновятся, Healthchecks снова зелёный
```

## Важно
- Уведомления должны идти **на почту или в Telegram лично владельцу**, а не только в чат бота:
  иначе при падении бота тревога не дойдёт.
- Проверка каталога ловит падение мини-приложения, но не бота: нужны обе проверки.
- `scripts/doctor.py` предупредит (⚠️), если `HEARTBEAT_URL` не задан — это значит,
  что внешний мониторинг ещё не подключён.

## Сколько стоит ИИ (E4)

`/health` показывает вызовы ИИ за сутки и оценку расхода.
Цена вызова — `LLM_COST_PER_CALL` в `.env` (по умолчанию 0.002 USD),
бюджет вызовов — `LLM_DAILY_BUDGET`. На 80 % бюджета бот один раз в день
предупреждает менеджера, дальше разбор идёт локально.
